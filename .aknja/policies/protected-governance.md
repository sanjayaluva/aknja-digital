# Protected Governance Policy

Protected invariants are not editable through ordinary runtime settings. Changes require founder-authored/reviewed code changes, tests, commit and explicit approval.

Protected items include tenant isolation, authentication rules, production approval, paid spend ceiling, zero-cost mode, secret access, audit retention/immutability, tool allow-lists, data-classification rules and emergency stop.

Runtime configuration may change operational values within protected bounds. Runtime settings cannot turn off security, bypass approvals or increase paid spend above the protected ceiling. AI cannot modify protected policy.
